# L4D2 USB Mod Importer · 求生之路 2 模组 U 盘导入工具

> **状态：研发中** —— 本仓库（U 盘导入工具）与本地版仓库 [l4d2-mod-manager-local](https://github.com/Yzy10086-l4d2/l4d2-mod-manager-local) 均处于研发阶段，功能持续迭代中，欢迎反馈问题与建议。

把 U 盘（或任意本机目录）里的 MOD 成套装进游戏：装完还能在同一个界面里开关、查冲突、一键回滚。

**它负责「从 U 盘往游戏里搬」；游戏目录里已有的 MOD 怎么管，用本地版。** 两个程序的界面长得像，别装错 —— 区别见下一节。

单个 exe（约 1.8 MB），依赖系统自带的 .NET Framework 4.x。**不需要安装、不需要 .NET SDK、不联网、不写注册表。**

|  | 本工具（U 盘导入） | 本地版 |

本地版仓库：<https://github.com/Yzy10086-l4d2/l4d2-mod-manager-local>

## 下载与安装

这个工具**没有安装程序**，一个 exe 就是全部。两种拿法：

**① 直接下载（推荐）**：到 [Releases](https://github.com/Yzy10086-l4d2/l4d2-usb-mod-importer/releases) 下最新的 `L4D2Setup.exe`，发布页附 SHA256，可以自己校验。

**② 自己编译**：clone 仓库后双击 `build.bat`，调用系统自带的 `csc.exe` 编译，不需要 .NET SDK、不联网。产物落在 `build.bat` 旁边；在 U 盘布局里则自动放回盘根目录。

环境要求：Windows 10 / 11（自带 .NET Framework 4.x）。Win7 需要先装 .NET Framework 4.x。

### 第一次打开

1. 双击 exe。程序没有代码签名，SmartScreen 可能拦一下：点「更多信息」→「仍要运行」
2. 这是**U 盘导入工具**：MOD 库在 U 盘上，装 MOD = 从库复制进游戏。只想管本机游戏目录（不复制文件）用[本地版](https://github.com/Yzy10086-l4d2/l4d2-mod-manager-local)
3. 游戏目录点「自动找」，或「浏览…」选到 `...\steamapps\common\Left 4 Dead 2`（有 `left4dead2.exe` 的那一层）
4. 左边勾要做的事，右下「开始安装」

配置写在 exe 旁边的 `L4D2MOD管理工具.配置.ini`，日志在 `_装机记录\`，删掉配置即恢复默认。游戏装在 `Program Files` 下时，装 MOD 需要右键「以管理员身份运行」。

### 想连平台组件一起装

「环境组件」里的 L4N / Skeeto / MQCam / dxvk 不在 exe 里，需要另外一份约 580 MB 的组件包（超过 GitHub 单文件限制，随 U 盘或网盘分发）。**只装 MOD 的话完全不需要它们。**

| 目录 | 大小 |
|---|---|
| `扩展平台\L4N平台` | 353 MB |
| `扩展平台\Skeeto` | 191 MB |
| `扩展平台\防闪退` | 30 MB |
| `扩展平台\MQCam` | 5.2 MB |

组件包**不必和 exe 放一起**：启动时依次看 exe 旁边、主库所在目录、以及各盘的 `游戏内容\求生之路2各项MOD\扩展平台`，哪个里面有 `防闪退` / `Skeeto` / `MQCam` 就用哪个。找不到也没关系 —— 缺的那几项会自动取消勾选，底栏写「增强包未附带（只装 MOD 不受影响）」，不会拿一片 FAIL 吓人。

要指到别处：「设置 → 组件包目录」填那一层的路径，或点「浏览…」；**留空 = 自动找**，下面的小字会实时显示这回实际用到哪个目录。填了就按填的来，保存后立即重查、左栏的「缺」跟着变。

### 库放在哪（U 盘目录结构）

如果想把整套随身带，按下面的结构放，exe 放 U 盘根目录就会被自动认出：

```
U盘根\
├─ L4D2Setup.exe
└─ 游戏内容\求生之路2各项MOD\
   ├─ 枪械\*.vpk
   ├─ 地图\*.vpk
   └─ ...
```

库放在别的盘也行：「设置 → MOD 主库 → 库所在盘」选盘，或直接指定任意文件夹。

## 它解决什么

一个 U 盘里堆着几百个 vpk，实际装机时会遇到三个麻烦：

1. **装哪几个全靠猜**：文件名看不出改了什么，两个包改同一把枪就互相覆盖
2. **开关状态散在文本里**：装完之后想关掉某一个，得去翻 `addonlist.txt` 手改
3. **装完不知道到底装了什么**：哪个进了 addons、哪个开着，全靠记忆

这个工具把这三件事收进一个窗口：列表里选、点一下装、勾一下开关，状态一眼看得见。

## 功能

### 1. MOD 库：U 盘主库

本工具只有一个口径：**库在 U 盘上**。扫描所选盘符的主库 + 附加库目录；游戏 `addons` 里与库条目**同名且同字节大小**的那份合并到库条目上，显示「已装」，不重复列。装 MOD = 从库复制进游戏，开关写到 `addonlist.txt`。

（想看本机游戏目录里已装了什么、只管开关不复制文件，用[本地版](https://github.com/Yzy10086-l4d2/l4d2-mod-manager-local)。）

- 支持独立 `.vpk`，也支持 `.zip` / `.rar` / `.7z` 里的 vpk（按包内路径逐条提取，保留目录结构）
- 三种包的**内容识别**完全一致：都只读包里那个 vpk 的目录表，判断「改了什么 / 落在哪个位置」，不读 `addoninfo.txt`
- 分类来自库里的文件夹层级，可手工改分类、改名、批量「全部导出」
- 候选列表支持多选（Ctrl / Shift / Ctrl+A）：选中 2 行以上时右键菜单只剩「删除选中的 N 个 MOD…」，
  压缩包里的和游戏目录里的一次性全拦下，确认后才删
- 装机前该知道的都写在底栏：目录对不对 / 游戏是不是还开着 / 有没有勾东西，主按钮跟着亮灭，
  不用点了「开始安装」再被一个个弹窗拦（可写性在后台探一次，不占 UI 线程）
- 可追加任意「库文件夹」，不限于 U 盘

### 2. 方案（Profile）

勾选一套 → 「存为方案」→ 下次「套用」一步到位。方案支持导入/导出/复制/改名，只记录「装哪些」，不含 vpk 本体，几十 KB 一个。

### 3. 套装总览与方案树

同一份数据，两种看法，勾选状态完全一致。顶部「总览」按钮切换，再点一下回方案树。

**总览**只回答一个问题：这套里，每个位置装的是哪个 MOD？它不是编辑器，但也不用换界面就能改。

- 左边是大类，每行带「已装 / 总位置」和一条覆盖率细条；**按住拖动可以换大类顺序**（和方案树共用同一份顺序）
- 右边是这个类的位置明细：位置名 → 已装的 MOD 名 → 大小 → 右边一个开关
- 开关开 = 这套里装它，点一下就关掉；关着时点开关会弹出候选，选一个就地换上
- 点 MOD 名字同样弹出候选，选完直接生效；「留原版」也在里面
- 没装的写「原版」灰着；库里一个 MOD 都没有的位置是空心点、不画开关（按了也没用）
- 顶部一句总账：几个位置有 MOD、几个 vpk、多大；右侧是覆盖率百分比

整块是 GDI+ 自绘（`OverviewModel` 算账、`OverviewLayout` 排版、`OverviewCanvas` 画和交互），数据直接取自方案树的位置表，不读磁盘、不联网。

**方案树**按「能被替换的位置」组织：枪械 → AK-47 / M16 / 手枪 → 医疗包 → 人物模型。

- 同一位置**单选取代**：选了新的 AK-47，原来那套自动取消
- 只改第一人称模型、音效、HUD 图标这类不动本体的（`Only1P` / `AnimOnly`），单独成栏，各自开关，可以和本体叠加
- 还没归类的 MOD 可以直接从候选列表**拖到树上归位**：位置 / 大类 / 分支三种落点，落点整行填色预览（蓝=可放、红=不行）

### 4. 内容识别

只依据 **vpk 的目录表**反推「这个包到底改了哪个模型 / HUD 图标 / 音效」，得出「改了什么」「影响面」「替换的模型名」。

刻意**不读** `addoninfo.txt` 里的作者自述——实测作者标题与真实内容经常对不上。

### 5. 冲突与重复检测

- **同位置冲突**：两个包改同一个 `v_rifle`，界面直接标出来，不会闷着头装
- **重复判定**：统一比 CRC32（独立 vpk 现算、zip 在解压流上算、rar 直接读包目录），三种来源可直接比较，不做体积相同之类的模糊猜测

### 6. 已装 MOD 开关

不卸载、不移动任何文件，只改游戏目录下 `left4dead2\addonlist.txt` 里的 `1` / `0`：

```vdf
"AddonList"
{
	"ak47.vpk"		"1"
	"m16.vpk"		"0"
}
```

- **顺序即覆盖优先级**：列表越靠下优先级越高，界面里的上移/下移改的就是这个顺序
- 文件头和认不出来的行原样保留，只替换 `{ }` 之间的正文
- 写入就是写入：不生成 `.装之前` 之类的副本，只改该动的那几行

### 7. 环境组件

一次装机可以顺带装好这些（**默认全不勾**，要用自己勾；缺文件会自动取消勾选并在底栏写明，不中断）：

- L4N 平台（`L4N_v*.zip` 或目录版）
- Skeeto + 素材包
- MQCam
- 防闪退（DXVK：`d3d9.dll` + `dxvk.conf`）
- cfg 预设
- Steam 启动项（写全部账号的 `localconfig.vdf`；参数串只清洗空白，不擅自改内容）

### 8. 回滚

- 删除就是真删：vpk 直接从磁盘移除，不进回收目录，删了就是没了
- 「一键还原」：删掉装进去的平台文件和本次铺的 vpk；原版 exe / `addonlist.txt` / `autoexec.cfg` 没有备份，需要原版请用 Steam 校验文件
- 日志留最近 40 个，多了自动清理

### 9. 设置

主界面右上角「设置」集中管理本机偏好：

- 游戏目录：可直接填路径、浏览或自动查找（MOD 就装到这里）
- 主库盘符：可直接选盘，或指定任意库文件夹；默认跟随程序所在盘
- 组件包目录：L4N / Skeeto / MQCam / dxvk 所在的那一层；留空自动找，填了按填的来，保存后立即重查并刷新左栏状态
- 减少动态效果：关闭按钮和状态切换的轻量过渡
- 附加库目录：额外参与扫描的库文件夹（管理后立即重扫）
- 配置与日志位置：直接打开所在文件夹，或运行环境自检

设置只写入本机配置，不修改已经装进游戏的文件。

### 10. 自检

界面全部功能都有对应的命令行自检入口，改完代码跑一遍看是否 0 FAIL 再发版：

```
--selftest       安装流程自检
--copytest       文件复制（有失败项时退出码非 0）
--safeself       写/删底线（原子落地、压缩包不误删、路径不越界；在数据卷上跑）
--addonself      addonlist 读写 / 开关 / 删除
--dupself        重复判定
--launchself     启动项写入（含 localconfig.vdf 改写，只碰临时文件）
--tweakself      参数套用

--plugself       插件组件：共享框架判定、目录解析（纯离线）
--plugtry=<目录>  拿真实库里的插件套装往这个（假的）游戏目录装一遍再一键还原，验完整链路
--dumpid         打印识别结果
--dumptree       打印方案树
--uitest         界面冒烟（配 --uitree / --uimenu / --uiaddons / --uicat= 等）

```

## 插件类 MOD（CFX 那类带 DLL 的）

有一类 MOD 光靠 vpk 装不完整：它除了进 `left4dead2\addons` 的 vpk，还带一套要落到
`<游戏>\bin\neko\plugins` 的 DLL（CFX 渲染框架 + 这把枪的插件）。少一个 DLL 的表现是
**进游戏手上空的**——不崩、不报错，最费时间。

这类包现在也是「勾一下装完」，不用再手动往 `bin` 里拷：

- **导入**：从文件夹导入时，vpk 旁边带 `bin\neko\plugins` 的整个收进库（不是只挑 vpk）；
  只收 vpk 的话插件留在原地，装机时层层往上找也找不到 —— 装完进游戏手上空的、声音却正常
- **认**：vpk 旁边有 `bin\neko\plugins` 就认；跨层找到的必须自带 `CFX\Weapons\<枪>\` 才认，
  只有 `l4n_plugin.h` 这类头文件、或平台自己的运行库（`扩展平台\L4N平台\...`）一律不算，
  免得「装个枪模把 L4N 的运行库当成自己的插件搬走」
- **分两类**：`CFX\Framework`、`CFX\renderer`、`CFX\cfx_host.ini` 是**共用框架**；
  `plugins\<x>.dll` 和 `CFX\Weapons\<枪>\` 是**这个包独占**
- **装**：vpk 铺完再铺插件（顺序反过来时，中途停下会出现「两把枪叠一起」）；同名同大小跳过，
  独占的不同版本覆盖前先快照，**共用框架已存在就保留现有版本**（多个 CFX 包各带一份框架，
  后装的静默降级会把先装的枪弄哑），要强更勾「覆盖重装」
- **还原**：只删记录里那几条独占文件（`shu_weapon.dll`、`CFX\Weapons\RAM7_Starlit\*`），
  共用框架留着——`bin` 下的东西在 Schema=3 之前的记录里一个都不碰
- **缺 L4N 会先说**：装之前发现没有 `bin\left4neko.dll` 就提示，因为插件根本不会被加载

列表里这类 MOD 的「改了什么」列会标 `含插件`，扫库日志会点名叫出来是哪些套装。

## 编译

不依赖 SDK / NuGet / 网络，用 Windows 自带的 C# 编译器：

```bat
build.bat
```

产物落在 `build.bat` 旁边（`_装机台源码\L4D2Setup.exe`）；如果脚本往上四层正好是盘根（U 盘布局），则放回盘根，保持老习惯不变。

文件名沿用 `L4D2Setup.exe`：U 盘根的布局、老快捷方式都不用改；**程序自身的名字**（窗口标题、设置页）显示为 `L4D2 USB Mod Importer`。

`.github/workflows/build.yml` 会在每次推送时用同样的 `csc.exe` 编译一遍；推 `v*` 标签时会自动建 Release 并把 exe 挂上去，别人可以直接下载。

## 命令行

```
L4D2Setup.exe [--game=<游戏根目录>] [--vpk=<单个vpk>] [--selftest] ...
```

不带参数就是正常界面。`--game=` 可跳过自动查找游戏目录。`--mode=local|usb` 可临时按指定模式运行并诊断扫描结果，不写回配置。

界面自检：`--treeself` 验总览（位置数、已装数跟方案树对得上，11 个大类都排得下，点一行命中的是同一个位置），`--treeshot` 存三张画布截图到 `_装机记录\overview*.png`，`--ovdump` 把整套摊成文本（`_装机记录\总览.txt`）。`--deskself` 验桌面（建卡是否有内容、JSON 能否被前端直接吃、摆位存取与落盘、本地服务真的发一次 HTTP 拿 state 和首页，结束会把 `桌面布局.ini` 逐字节还原），`--desklaunch` 真开一次桌面窗口（浏览器起没起来、重复点「桌面」会不会换掉窗口、关掉之后进程退没退），`--uikeys` 验树的键盘与拖动路径。`--deskserve=秒数` 只起服务不弹窗口（给无头截图用）。

桌面页自己还带两个不用手点的入口：`?tap=卡片,行` 与 `?drag=卡片,dx,dy` —— 页内合成一次真实的 pointerdown/move/up，走完整条命中链路，结果写进 `document.title`，配 `--dump-dom` 就能验点击 / 拖动有没有通。

## 已知边界

- 只在 **Windows + .NET Framework 4.x** 下测试过；WinForms 界面，不跨平台
- `.zip` 纯托管读写，不依赖外部程序；`.rar` 需要装 WinRAR；`.7z` 读目录表用系统自带 `tar.exe`（Win10 1803 起），解压安装仍要 WinRAR。缺了这些，对应格式的包只会读不出内容、装不进去，其它格式不受影响
- 会修改玩家本机的游戏目录、`addonlist.txt` 和 Steam 启动项，运行前请确认游戏目录选对了
- 仓库里只有工具源码，**不含游戏本体，也不含任何 MOD 内容**
- 不允许删游戏目录里的文件（提示去资源管理器处理），这是故意的：库里那份才是母本
- 插件组件只认真实文件夹里的 `bin\neko\plugins`：压缩包（zip / rar / 7z）里带的那份不识别，
  也没法「只有插件、没有 vpk」的纯插件包单独列出来
